How it works

One binary, one directory

Ambrogio is a single static binary beside a single SQLite file. That directory is the whole system — lose it and everything the hub knows is gone, which is why it is treated as the thing that cannot be lost.

The runtime

  • One binary. It serves a small HTTP API and one SSE stream, and it embeds its own operator page — HTML, CSS and JavaScript are inside the executable, so nothing is read from disk at run time.
  • Resident agent processes. Agents are separate processes spoken to in the Agent Client Protocol (omp acp). The hub starts them, resumes them, and retires them; a session is a file, so a resume continues the conversation instead of starting over.
  • Reconciliation on startup. Nothing about the previous run is assumed: every agent is marked stopped, then each one that is not retired and has a stored session is brought back; messages handed out and never finished go back in the queue for everyone.
  • One writer per folder. Work happens in a folder, and a folder has one writer at a time — which is how two hands never overwrite each other.

How this site is delivered

This page travels the same lane as the rest of the lab: a git push builds a container image, and the cluster follows the tag.

git push→ GitHub Actions→ Docker Hub→ Flux image automation→ Kubernetes rollout
  1. A push to master starts the publish workflow.
  2. The workflow builds the image and pushes it to Docker Hub as tazzo/tazlab-ambrogio-site, tagged latest and ambrogio-site-<run>-<sha>.
  3. Flux polls the registry, selects the newest tag by its run number, and commits the new reference back into the cluster repository.
  4. The Flux Kustomization reconciles the Deployment and the new image rolls out.

Served static, behind TLS

The pod is nginx serving static files on port 80 — no database, no application server, nothing computed at request time. It is exposed through a Traefik ingress with a certificate issued by cert-manager from Let's Encrypt, and the site answers at ambrogio.tazlab.net over HTTPS.
