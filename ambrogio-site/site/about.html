About

Built in the lab it runs

Ambrogio is part of tazlab.net, a small homelab run on its own hardware and documented in public.

The lab

tazlab.net is a Kubernetes cluster on bare metal and Proxmox, with GitOps at its centre: repositories hold the desired state, Flux reconciles it, and a push is a deployment. The lab publishes a blog, a wiki and a teaching site, and Ambrogio is the agent hub that the operator talks to when he wants work done instead of work to do.

Why it exists

The lab already had automation: pipelines that build and ship, and schedules that run. Ambrogio adds something those cannot — an agent that can be asked in words, that keeps a queue of the work it was given, and that leaves a report behind each step. It is meant to be the place where work is opened, carried, and remembered.

How it is constrained, on purpose

  • It is one directory. There is no service unit, no container and no backup of the hub's own store: the operator starts it by hand, and the data is treated as the one thing that cannot be lost.
  • What opens does not start. Work that is proposed waits for the operator to accept it and to say how many steps it may take. The engine carries it from there, oldest first, one writer per folder.
  • The engine does not judge prose. Whether a delivery holds is checked by deterministic code: the declarations are present, and the things they name exist where they say.

This site

A static site — no database, no application server, nothing computed at request time. The source is a repository of plain HTML and one stylesheet; the image is built by GitHub Actions and delivered by Flux, exactly like the blog, the wiki and the teaching site.
